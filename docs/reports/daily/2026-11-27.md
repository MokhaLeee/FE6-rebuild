### 地图治疗动画结束时单位消失 4–5 帧（6b18ada）

夜间收尾时发现：HealingFocus 和 post action heal 的动画播完、回到地图待机时，
被治疗的单位会消失约 4–5 帧（既看不到 Mu，也看不到地图精灵）。

- 根因一：`muskillanim_init()` / `map_heal_anim_init()` 里的 `RefreshUnitSprites()` 在行动
  期间 `gMapUnit` 被临时清空时会把单位的 `map_sprite` 置成 NULL；动画期间靠 Mu 显示，
  这个问题被掩盖住了；
- 根因二：动画 end 提前 `EndMu()`，行动收尾（`PlayerPhase_WatchActiveUnit` /
  `PlayerPhase_FinishAction`）还没把地图精灵交回来，于是出现「Mu 没了、地图精灵还没回来」
  的空档；
- 修复：
  - init 不再 `RefreshUnitSprites()`，只 `EndAllMus()` 清残留 Mu；
  - end 只 `ShowUnitSprite()` + `ForceSyncUnitSpriteSheet()`，Mu 留给行动收尾的
    `EndAllMus()` 结束，地图精灵随后接管；
  - `UnitSpriteHoverUpdate()` 在 `StartMu()` 失败时不再隐藏地图精灵，重置悬停时钟重试。
- `PlayerPhase_FinishAction()` 保持原版：它只是暴露点，不是根因；把对它的修改回退后重跑
  gbarun 逐帧验证，仍然没有空洞；
- 新增 `docs/map-heal-flicker.md`：记录排查流程、`--probe` 方法、根因和修复。

### 第一章魔法战斗动画卡死：gSpellAnimBgfx 越界踩坏 banim 状态（e87c7a3，今日重点）

**现象**：开 `CONFIG_DEBUG_CH0_EVENT` 后进第一章，开局事件连跑三场 `EvtFightScript`，
第三场（Lugh 用火焰打敌弓兵）必卡——画面停在闪避那一帧，按 A / START 都没反应，
只差把模拟器关掉。

**排查过程**

1. gbarun 不带按键跑 20000 帧：帧 3800 之后画面哈希恒定、`gPlaySt+0xE`（chapter）一直是 1，
   `DONE` 正常返回，说明不是崩溃也不是在等输入，而是没有能推进流程的进程。
2. `--gdb-at` 挂上去 dump `gProcTreeRootArray`，8 棵树里只剩两个：
   `ProcScr_EfxAvoid`（重复 `EfxHpBar_MoveCameraOnEnd`）和 `ProcScr_EfxSpellCast`
   （重复 `EfxSpellCast_Pause`）。地图主循环 `ProcScr_BmMain`、事件进程 `ProcScr_Event`
   都已经没了，只剩一个泄漏的 `ProcScr_TalkSkipListener`。
3. 断在 `EvtCmd_FightScript` 打印 pid：`1→31`、`1→69`、`37→72` 三场都进了
   `BeginBattleAnimations()`，但 `EvtCmd_NextChapter` 一次都没命中 —— 卡在第三场的 banim 里。
4. 关键量：`gEfxBgSemaphore = 0xFFFFFFFF`。`EfxHpBar_MoveCameraOnEnd()`
   （`banim_efxhpbar.c:150`）要等 `gEfxBgSemaphore == 0 && gEfxSpellAnimExists == 0`
   才 `Proc_Break`，于是弓兵闪避特效永远不结束，`gEkrHpBarCount` 卡在 1，
   EkrBattle 收不了尾。
5. 在 `gEfxBgSemaphore`（0x020069F0）上打 hardware watchpoint，抓到完整链条：
   - `EkrEfxStatusClear()` 开场清零；
   - `NewEfxMagfcastBG()` 的 `gEfxBgSemaphore++` → 1；
   - **一次 `LZ77UnCompWram` SWI 把它写回 0**；
   - 该 BG 特效结束时 `EfxMagfcastBG_Loop()` 再 `--` → 0xFFFFFFFF。
6. 那次 LZ77 来自 `SpellFx_RegisterBgGfx(Img_EfxMagfcastBG, 0x2000)`
   （`banim_ekrutils.c:319`）：`LZ77UnCompWram(img, gSpellAnimBgfx)` 按图里的头解压
   **0x2000** 字节，而 `gSpellAnimBgfx` 只有 **0x1D00**，尾部 0x300（这段解压数据正好全是 0）
   落到紧随其后的 EWRAM 上：`0x020069C4..0x02006CC4` 正好覆盖
   `gEkrHitNow` / `gEfxBgSemaphore` / `gEfxSpellAnimExists` / `gpProcEfxSpellCast` 等。
7. 反向验证：watchpoint 命中后把下溢值用 gdb 改回 0（两次），战斗动画立刻收尾，
   事件继续跑到 `EvtNextChapter(CHAPTER_2)` —— 因果确认。

**根因**：真正丢的不是「0x1D00 这个小了 0x300」，而是 **EWRAM 声明顺序**。
源码里是 `gEkrHitNow` → `gSpellAnimBgfx` → `gEkrBarfxBuf` → `gEkrTsaBuffer`，
GCC 默认按**逆序**发射顶层数据，链接后变成
`gEkrTsaBuffer(0x020039C4)` → `gEkrBarfxBuf(0x020049C4)` → `gSpellAnimBgfx(0x02004CC4)`
→ `gEkrHitNow(0x020069C4)`。原版把 0x300 的经验条框缓冲排在 `gSpellAnimBgfx` 后面，
0x2000 解压溢出的那 0x300 正好落进这块「此刻没人用」的 barfx 缓冲；逆序之后同一段溢出
踩的是效果状态量，于是每次魔法攻击都会把 `gEfxBgSemaphore` 清掉、结束时再 `--` 成 -1，
后面任何等待它归零的特效（闪避 / 血条 / 死亡）都会永久阻塞。

**修复**（照 `~/fe6` 的改法）：

- `gSpellAnimBgfx` 扩到 `0x2000`——它本来就该装得下一整张法术 BG 图，删掉独立的
  `gEkrBarfxBuf`；
- 经验条框改用同一块缓冲的尾部：`buf = gSpellAnimBgfx + 0x1D00`、`buf0 = buf + 0x80`
  （`banim_ekrbattle.c` 的 `EkrBattleExecExpGain()` / `EkrBattleWaitExpBar()`）；
- `banim_ekrbattle.c` 本地保留 `#define gEkrBarfxBuf ((u16 *) (void *) (gSpellAnimBgfx + 0x1D00))`，
  5 处调用点仍是 `gEkrBarfxBuf` / `gEkrBarfxBuf + 0x80`，和原版源码写法一致，
  后续同步上游不会平白冲突；
- 链接后布局：`gEkrTsaBuffer 0x020039C4 (0x1000)` → `gSpellAnimBgfx 0x020049C4 (0x2000)`
  → `gEkrHitNow 0x020069C4`，解压刚好填满，不再越界。

**范围**：解压长度 0x2000 的法术 BG 图不止 magfcast，还有 Fire / Elfire / Alacalibur /
AureolaBG2 / Sleep / CriricalEffect / Fae / Forblaze 等，之前每次都在踩后面的变量，
只是没赶上正好清掉 `gEfxBgSemaphore` 这种临界量。

### cskillsys gaiden magic 移植起步（2d511cb / b2b9900 / 61a98af / 335966f / 7c3dec3 / 7dc3cc1）

- 菜单 `OnDraw` 每帧调 `MakeTargetListForWeapon()`（O(地图)）和 `BattleGenerateUiStats()`；
- 新增 action 类型的边际成本是 20+ 个文件的 case（`PostActionSkills` 12 个、
  `ActionFix.c` 3 个整函数替换、AI 特判）。

**已完成的地基**：

- **2d511cb** 新增 `GetItemFromSlot()`，把「slot → item」收敛成一个入口，覆盖背包 /
  溢出 / 斗技场 / 弩车。`SetBattleUnitWeapon()` 不再在每个 case 里各写一次取值，
  `BattleInitItemEffect()`、射程查询、杖治疗量都改走它；负数 slot 直接返回 0，
  不再先越界读再丢弃。
- **b2b9900** `BattleInitItemEffect()` 原来无条件 `has_inventory_weapon = TRUE`，
  而 `BattleApplyItemEffect()` 会按 slot 写回 `unit->items[]`。改成按 slot 真实取值
  （只有 0–4 才算背包武器），把「misc action 也认领背包武器」这个错误语义修掉。
- **61a98af** 列表层。`GaidenMagicList`（bmag/wmag 各 7）+ 两张表
  （`gGaidenPinfoConfigList` 按 `pinfo->id`、`gGaidenWeaponCostList` 按 iid）+
  `CanUnitUseGaidenMagic(Now)`。列表不落存档，靠 `pinfo/jinfo/level/id` 签名失效重建，
  单实例放 EWRAM。相对上游改了一处：不用 256 字节位图加两遍倒序扫描，改成单遍顺序
  遍历加线性查重，表顺序即槽位顺序。
- **335966f** slot 解析。`GetItemFromSlot()` / `SetBattleUnitWeapon()` 认 9–22，
  书以满耐久（`0xFF << ITEM_USES_SHIFT`）发出，空槽返回 0 而不是 `0xFF00`；
  gaiden 槽必须 `has_inventory_weapon = FALSE`，否则战斗结束会往 `items[9..22]` 写回。
  `UpdateEquipInfoWindow()` 补同一分支；`BattleGenerateRealInternal()` 采信
  `gAction.item_slot` 里的书，其余战斗仍是 `-1` 自动装备。
- **7c3dec3** `GetGaidenMagicAutoEquipSlot()` 加 `GetUnitEquippedWeapon(Slot)` 兜底，
  背包无武器的单位（含敌方 AI）现在会用书打架。背包有武器的单位不受影响，
  循环先返回。
- **7dc3cc1** 射程。新增 `GetGaidenMagicWeaponReach()` / `GetGaidenMagicStaffReach()`，
  三个 `GetUnit*Reach()` 保持只报背包，全局范围显示自己 OR 进去；`GetUnitUseBits()`
  也认书，否则「只有书」的单位连 `DisplayUnitActionRange()` 的门控都过不去。

**被回退的方案**：试过把书直接列进 `MenuInfo_UnitAttackItem`（背包 5 项加书 4 项），
复用「攻击 → 选武器 → 选目标」两步流程。`MENU_MAX_ENTRIES = 11`、菜单每项 2 tile、

**现状**：自动战斗与敌方 AI 会用书，范围显示含书，但玩家没有手动选书的入口，
HP 消耗也还不扣。写了 `src/Core/GaidenMagic/README.md`，记槽位图、列表层、射程契约、
回退原因，以及 FE6 特有的坑（`Unit::id` 是 `i8`、`UNIT_FACTION` 是 `id & 0xC0`、
没有 `CA_PROMOTED`、`MENU_MAX_ENTRIES = 11`）。

## 问题与风险

- **经验条框与法术 BG 图共用 `gSpellAnimBgfx`**：靠「两者不同时出现」维持。如果以后有流程
  在法术 BG 图还挂着的时候播经验条（或反过来），尾部 0x300 会被互相踩。

  加了 `-fno-toplevel-reorder`）。这次只修了 banim 这一处，其它 overlay 是否也有
  「相邻变量被当成缓冲区余量」的默契还没系统检查过。

  以后排查 banim 打开它时，记得别把开关一起提交。
- 战斗系统拆分（7ac514b）只有编译验证，没有回归跑战斗流程；banim 变量搬家
  （7850213）同样只有编译验证。
- 地图治疗现在同时存在两种写法实例（`HealAfterAction.c` 走壳 proc，
  `HealingFocus.c` 自己接回调），后续加新 heal 技能时按

  里记的检查点仍适用于其它自定义地图动画。
- **两份 mss 顶层脚本要一起改**：`ProcScr_modern_statscreen` 和
  `ProcScr_modern_prep_statscreen` 的共享段（`PL_MSS_SLIDE_UNIT_IN` / `PL_MSS_IDLE` /
  `PL_MSS_SLIDE_PAGE`）是复制的，改其中一份必须同步另一份；代码里注释已标明。

  地图变体仍沿用地图留下的状态；如果以后有调用方不再满足这个前提，面板会整块读错图。

  HP 消耗也还不扣，但自动战斗和敌方 AI 已经会用书打架。现在拿去实机验证会得到
  偏强的平衡结论。

  攻击菜单塞满 5 背包 + 7 书会到 184px（屏幕 160px）。要么改菜单框架，要么做分页。

  会赋 `gAction.item_slot`，属于预留代码；如果长期接不上菜单，考虑删掉避免误读。

  等于免费施法；接 HP 扣血前不要据此调平衡。
