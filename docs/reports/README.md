# 报告汇总（日报 / 周报 / 月报）

本目录是 fe6-rebuild 的提交报告归档。硬性条款写在 `AGENTS.md` 宪法的
「报告对齐审查」一节，本文件是执行细则。

**前提：不是每天都有提交。** 没有提交的日子不需要日报；一整周没有提交就不需要
周报；一整月没有提交就不需要月报。报告的必要性由「该周期内是否有非报告提交」
决定，而不是由日历决定。

## 1. 目录

```
docs/reports/
├── daily/         日报 YYYY-MM-DD.md
├── weekly/        周报 YYYY-Www.md（ISO 周，周一至周日）
├── monthly/       月报 YYYY-MM.md
├── templates/     三份模板
├── epoch.txt      制度生效日
├── review-log.md  审查记录（review.sh --log 追加）
└── README.md      本文件
```

报告按**提交日期**归档：`daily/2026-11-16.md` 记录 11-16 当天产生的提交，
哪怕你是 11-17 早上才补写。

## 2. 锚点（覆盖提交）

每份报告开头必须有两行锚点：

```
覆盖提交: ebc0b077a413c52125c77926ef981de1c5dfe845
记录时间: 2026-11-16 18:20 +0800
```

- `覆盖提交`：写报告时仓库 HEAD 上最近的一个**非 `docs/reports/` 提交**。
  含义是「截至这个提交，本报告已经覆盖」。
- `记录时间`：写入锚点的本地时间（Asia/Shanghai）。
- 锚点由 `./tools/reports/stamp.sh` 写入，也可以手写；不要写分支名或 `HEAD`，
  必须是能 `git rev-parse` 出来的提交。

**报告提交要和代码提交分开**：只提交 `docs/reports/` 下的文件。审查会把
`docs/reports/` 的提交从「基准提交」里排除，混在一起提会让锚点看起来落后。

## 3. 什么时候需要哪份报告

| 报告 | 需要的前提 | 文件 |
|---|---|---|
| 日报 | 该自然日有非报告提交 | `daily/<当天>.md` |
| 周报 | 该 ISO 周有非报告提交 | `weekly/<ISO 周>.md` |
| 月报 | 该自然月有非报告提交 | `monthly/<自然月>.md` |

- 某天没有提交：不要求日报；写了也不判错。
- 某周没有任何提交：不要求周报。
- 某月没有任何提交：不要求月报。
- 只有 `docs/reports/` 提交的日子，视为没有提交。

## 4. 更新时机

- **日报**：只在用户明确要求时更新（「写今天的日报」「更新日报」）。
- **周报 / 月报**：同样只在用户要求时更新；周期结束后的审查会提醒补写。
- 代理不得擅自新建或改写报告正文；审查只负责提醒，不代写内容。

## 5. 每日审查（每天第一次提交前）

宪法要求每个自然日第一次 `git commit` 之前跑一次审查：

```sh
./tools/reports/review.sh            # 审查昨天
./tools/reports/review.sh --date 2026-11-16
./tools/reports/review.sh --log      # 结论追加到 review-log.md
./tools/reports/review.sh --quiet    # 只报失败项（hook 用）
./tools/reports/review.sh --no-backlog   # 不检查历史漏报
```

判定口径（基准日 B = 审查日的前一天）：

| 报告 | 何时强制 | 判定 |
|---|---|---|
| 日报 | B 日有非报告提交 | 必须存在，锚点**等于** B 日最后一个非报告提交 |
| 周报 | B 所在周有提交，且该周已结束（周日已过） | 必须存在，锚点**覆盖**该周最后一个非报告提交 |
| 月报 | B 所在月有提交，且该月已结束 | 必须存在，锚点**覆盖**该月最后一个非报告提交 |

- 日报锚点更晚（报告晚写、把后一天算进来）或更早（落后）都算不一致。
- 周报 / 月报锚点只要覆盖周期末提交即可，落后的数量会打印出来。
- 周期未结束：周报 / 月报缺失或落后只记为「提示」，不计失败。
- 周期结束日早于 `epoch.txt` 的，整个周期跳过。
- 「基准提交」和「报告锚点」都排除 `docs/reports/` 自身的提交，避免
  「提交报告 → 报告落后」的死循环。

## 6. 历史漏报（backlog）

`review.sh` 每次还会扫一遍 `epoch.txt` 之后、已结束、有提交但没有报告的
日 / 周 / 月，在结论里列为「日报缺失 N 天 / 周报缺失 N 周 / 月报缺失 N 个月」。
补上后自动消失；要关掉用 `--no-backlog`。

## 7. 审查不通过时

1. 先把结论告诉用户：缺哪份报告、差哪些提交（`review.sh` 会列出）。
2. 用户同意补写后，按 `templates/` 下的模板生成报告，写清对应周期的工作和
   提交，不要只写锚点不写内容。
3. 写入锚点：

   ```sh
   ./tools/reports/stamp.sh daily 2026-11-16
   ./tools/reports/stamp.sh weekly 2026-W47
   ./tools/reports/stamp.sh monthly 2026-11
   ```

   省略 commit 参数时取当前 HEAD 上最近一个非 `docs/reports/` 提交。
4. 报告单独提交，然后重新跑 `./tools/reports/review.sh` 确认通过。

## 8. 可选：提交前自动提醒

```sh
./tools/reports/install-hook.sh     # 安装 pre-commit（warn-only，不阻断提交）
./tools/reports/install-hook.sh --uninstall
```

hook 每个自然日第一次提交前运行一次审查，把结论打印到终端；无论结果如何都
放行提交（要跳过用 `git commit --no-verify`）。装不装由用户决定，默认不装。

## 9. 首次启用与历史补写

`epoch.txt` 默认写建立制度的当天（2026-11-16），早于该日结束的周期不要求
报告，因此不会一上来就追着历史要报告。要回补更早的报告，把日期改早。

## 10. 常见问题

- **好几天没提交**：这几天都不需要日报，审查只报「当天没有非报告提交」。
- **某天只有 `docs/reports/` 的提交**：视为无提交，不要求报告。
- **忘了审查**：下次运行时按基准日补上；`review-log.md` 只记录实际运行过的审查。
- **一次提交跨天**：以提交时间（committer date）为准，与 `git log` 默认排序一致。
- **周报/月报还没到周期末**：审查只提示，不判失败；周期结束后再补。
