## 1. 设计目标

1. **让每个角色有"身份"**：职业给打法，人物给个性，成长给惊喜，武器等级给专精。
2. **不破坏 FE6 的节奏**：FE6 敌方基本无技能，因此玩家侧技能以"小幅、条件化"为主，避免变成无双。
3. **可读**：一眼能看出"这角色该干什么"，而不是堆一串 +2。
4. **可落地**：优先使用内核已有技能；新技能必须能挂到现有钩子上实现。

### 1.1 等级机制改动带来的结构变化（v2 核心）

v2 设定：**转职时等级不重置，人物等级持续累积**。由此：

- 原版 GBA 的"职业等级"概念消失，**不再设计"转职后职业等级技能"**。
- 职业侧压缩为两类：**职业固定技能（转职/加入即有）+ 职业精通技能（转职后成长兑现）**。
- 每个职业精通技能 **最多 2 个**，用"转职后累计等级"作为触发条件：
  - 精通 I：转职后累计 **+5 级**
  - 精通 II：转职后累计 **+10 级**
- 未转职职业（盗贼、舞者、吟游诗人、龙人、运输队）改用 **人物等级 15 / 25** 触发。

这样设计的好处：

1. **转职后仍有明确的成长目标**（两个精通技能），而不是转职即"技能毕业"。
2. 与"等级持续累积"完全兼容：`unit->level - promo_level` 就是"本职业投入"。
3. 职业侧技能总数可控（2 固定 + 2 精通），不会挤压人物技能。

### 1.2 六类来源

| 来源 | 载体 | 获取条件 | 本文标记 |
|---|---|---|---|
| 职业固定 | `gSkillJTable` 2 槽 | 加入/转职即得，常驻 | `J:` |
| 职业精通 | 新增 `gSkillPromoTable`（每职业 ≤2） | 转职后 +5 / +10 级；未转职职业用 Lv15/25 | `JP1/JP2` |
| 人物固有 | `gSkillPTable` 1 槽 | 加入即得，常驻 | `P:` |
| 人物等级 | `gSkillPreloadPData`（5/10/15/20/25 节点） | 人物总等级达到节点 | `Lv5/10/…` |
| 武器精通 | 新增 `gSkillWexpTable`（C/B/A/S） | 对应武器熟练度达到 C/B/A/S | `W:C/B/A/S` |
| 特殊 | 剧情事件 / 专属武器 / 道具 | `LearnSkill` 授予 | `S:` |

> 六类里，"职业固定"与"职业精通"是 v2 的职业侧双段；"人物等级"与"武器精通"是人物侧两条成长线；"特殊"是剧情奖励。

### 1.3 平衡基调

- 职业固定：**功能性**，数值低（+10 命中、+2 攻之类），2 个。
- 职业精通：**职业的质变点**，1~2 个，获取晚（转职后 5/10 级），可以比固定技能明显更强。
- 人物固有：**1 个差异点**，让同职业的两个角色玩法不同。
- 人物等级：**成长兑现**，Lv5/10 补强，Lv15/20 质变，Lv25 终盘。
- 武器精通：**专精深度**，C/B/A/S 逐级强化该武器系的"身份"。
- 特殊：**剧情奖励**，每人最多 1 个。

## 3. 职业技能（`J:` / `JP:`）

职业侧分两段：**固定技能（`J:`）** 写 `gSkillJTable`，**精通技能（`JP:`）** 写新增的 `gSkillPromoTable`。
原则：上位职业继承下位职业的 1 个固定技能，再加 1 个质变技能；精通技能不继承，按"转职后累计等级"单独判定。
同职业线内的角色共享这套"职业身份"，彼此靠 §4 的固有技能区分。

### 3.4 职业精通技能（`JP:`，v2 新增）

   （按 5 级一格，`skills[level/5*SKILL_ROM_DATA_AMT + i]`）。
5. **武器表**：新增 `gSkillWexpTable[pid][ITEM_KIND_*][4]`，在 `setup_skill_list()`
   中按 `unit->wexp[kind] >= WEXP_C/B/A/S` 追加。

### 9.2 逻辑层

| 需求 | 现有钩子 | 需要新增 |
|---|---|---|
| 人物等级自动习得 | 内核 `UnitAutoLoadSkills` / `TryAddSkillLvupPConf`（FE6 尚未移植） | 移植 `LoadSkill.c` 的 lvup 部分，或直接在 `setup_skill_list` 里按 level 查表 |
| 职业精通判定 | `setup_skill_list()` | `ADD_PROMO_SKILLS(unit)`：读 `gSkillPromoTable[职业]`，用 `unit->level - unit->promo_level` 对照 +5/+10 |
| 转职记录 | 转职流程 | 在转职时写 `unit->promo_level = unit->level`（新增字段，或复用隐藏字节） |
| 未转职职业精通 | 同上 | 分支：`promo_level == 0` 时改用 `unit->level >= 15/25` |
| 武器熟练度自动习得 | `setup_skill_list()` | `ADD_WEXP_SKILLS(unit)` 函数 |
| Boss 固定技能 | `gSkillPTable` 已可覆盖 Boss PID | 无 |
| 三角攻击 | 战斗菜单 + 战斗动画 | 新菜单项 + 三次攻击的伤害合并 |
| 原创技能效果 | `src/SkillEffects/` 已有 Attacker/Defender 两派 | 按 §8 钩子逐条加 |

### 9.3 建议顺序

1. 先只做 §3.1~3.3 + §4（纯数据），跑 `./tools/emu/testmenu-tests.sh` 确认不崩。
2. 再做 §3.4 职业精通：先加 `promo_level` 字段与 `ADD_PROMO_SKILLS`，用"转职后 +5/+10"验证。
3. 再植入 §5 人物等级表；注意 `UNIT_DYNAMIC_SKILLS_COUNT` 只有 4，若走"全部常驻"路线，
   §5 会撑爆 `unit->skills[4]`，**必须改用内核的 preload + 8 槽 RAM 列表**，或在
   `setup_skill_list()` 里动态查表（不占存档字段，推荐）。
4. §6 武器表依赖 §9.2 的 `ADD_WEXP_SKILLS`。
5. §8 原创技能按 A→B→C→D 顺序，每个技能单独提交（需用户许可）。

### 9.4 v2 的字段改动

| 字段 | 位置 | 用途 |
|---|---|---|
| `promo_level` | `struct Unit`（新增 1 字节） | 转职时的等级，用于 `level - promo_level` |
| `gSkillPromoTable` | 新表 | 每职业 ≤2 个精通技能 |
| `gSkillWexpTable` | 新表 | 武器系 C/B/A/S 技能 |
| `gSkillPreloadPData` | 新表 | 人物等级 5/10/15/20/25 技能 |

> 若不想改 `struct Unit`，也可以把 `promo_level` 存到 BWL/单位扩展区；但 v2 的"转职后累计等级"是核心机制，建议显式字段。

## 10. 平衡性自检

1. **避免"技能叠加爆炸"**：`Faire` + `Crit` + `Astra` 同时存在时，剑圣的期望伤害会翻倍；
   建议同一角色 **最多 1 个"伤害倍率型"技能**（Astra/Colossus/Impale 三选一）。
2. **避免"必中 + 必杀"**：`Hawkeye`（必中）只给 Igrene/Klein 这类专属弓手，
   不要与 `SureShot` 同人共存。
3. **避免"全免伤"**：`GreatShield`、`Barricade`、`Multiscale` 只在单一角色身上出现，
   且 Boss 的 `Nihil` 能封印它们。
4. **成长率补正**：Karel 在本仓库数据中 `growth_hp=210`（原版 FE6 的成长怪物设定），
   因此其 Lv 技能不需要再堆数值，重点放在"剑圣"的暴击与必杀上。
5. **Lv25 与职业精通的时间线**：等级不重置后，Lv25 在转职后仍可自然达到；
   职业精通（转职 +5/+10）与 Lv25 可能同时到，注意不要让同一角色在同一级拿到两个大招。
   高等级角色（Karel/Niime/Yoder）加入时按当前等级回溯补发，避免"加入即毕业"。

## 12. 待确认问题

1. **职业精通的触发条件**：本稿用"转职后累计等级 +5/+10"。备选：
   - 按"转职后战斗次数"（更贴近"职业熟练"，但要新计数器）；
   - 按"转职后获得的经验值"（与等级差等价，但更直观）。
   目前"等级差"实现最简单，推荐。
2. **未转职职业的精通**：本稿用人物等级 15/25。是否改为"加入即给 1 个精通、Lv25 再给 1 个"？
3. **职业精通是否应该与武器精通联动**（例如"剑 S 且转职后 +10"才给剑圣精通）？本稿暂不联动。
4. **技能是否全部常驻，还是装备槽限 3~5 个？** 全部常驻更像"角色成长"，装备槽更像"构筑"。
   本稿按常驻设计，若要做装备槽需改 `UnitAutoLoadSkills` 的槽位数。
5. **敌人是否也吃技能系统？** 若只强化玩家，需要同步提高敌方数值或给 Boss 技能。
6. **三角攻击是否保留？** 这是 FE6 原作的标志，但实现成本最高（菜单 + 动画）。
7. **Canto 的强度**：建议限制为战后最多再移动 2 格，且不能再攻击/用杖。
